# Round 2 (Steady Hands) calibration, 2026-09-26

Hardware: Arduino UNO R4 WiFi, Grove 3-Axis Digital Accelerometer LIS3DHTR on the Grove I2C port (address 0x19, WHO_AM_I 0x33), Grove button on D2, rotary angle sensor on A0. A laptop stood in for the Raspberry Pi.

Before the game sketch, an I2C scanner read the LIS3DHTR at rest at about x=-262, y=272, z=903 mg (|a| about 980 mg, so about 1 g), with 3-8 mg of sample-to-sample jitter.

Command: `python pi/main.py --port /dev/ttyACM0 --round 2 --calibrate`. Raw console output, unedited:

```
Arduino: Round 2 (Steady Hands) active, accelerometer LIS3DH@0x19
   calib #1: tremor 68.0 mg RMS | peak 295.7 mg | samples 500 | (claim 56 ignored)
      so far: min 68.0 | median 68.0 | max 68.0 mg RMS over 1 hold(s)
   calib #2: tremor 20.7 mg RMS | peak 134.4 mg | samples 500 | (claim 56 ignored)
      so far: min 20.7 | median 44.4 | max 68.0 mg RMS over 2 hold(s)
   calib #3: tremor 1493.6 mg RMS | peak 2637.3 mg | samples 500 | (claim 56 ignored)
      so far: min 20.7 | median 68.0 | max 1493.6 mg RMS over 3 hold(s)
```

What each hold was, as reported by the player:

| Hold | What the player did | Tremor (mg RMS) |
| --- | --- | --- |
| #1 | Held in the hand as still as possible | 68.0 |
| #2 | Sensor lying on the table | 20.7 |
| #3 | Shaken hard on purpose | 1493.6 |

Every hold got the full 500 samples (5 s at 100 Hz).

Thresholds chosen from this (see `pi/config.py`):

- `STEADY_REST_MG = 30`. Below this the sensor was set down, not held, and the hold is rejected. This sits between the table (21) and the hand (68).
- `STEADY_BEST_MG = 35`, so 100 points. A still hand at 68 scores about 93.
- `STEADY_WORST_MG = 500`, so 0 points. A hard shake is far beyond it; a small tremble around 200 mg scores about 65.

After this, scored rounds with the ElevenLabs verdict were played on the same hardware and worked end to end. This is a single session with one player, so it should be re-run with more people before the demo.
